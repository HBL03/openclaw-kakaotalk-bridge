# 사용과 문제 해결

## 명령과 알림

앱의 상태가 **새 명령 대기 중**으로 바뀐 뒤 본인 방에서 `!ai ping`을 새로 보냅니다.
`!ai오늘`은 명령이 아니며 `!ai` 뒤에는 공백이나 줄바꿈이 필요합니다. 빈 명령은 상태 창에
사용법을 표시합니다. 예: `!ai 내일 오전 일정 정리해 줘`.

답변을 다시 관찰해도 새 요청으로 실행하지 않습니다. 앱을 재시작한 경우 기존에 보이던 메시지는
재처리하지 않으므로, 이전 명령에 답변이 없으면 상태를 확인하고 새로운 명령을 보내세요.

알림은 OpenClaw의 Cron `announce`를 사용하며 전송 설정을 명시합니다:

```json
{"mode": "announce", "channel": "kakao-local", "to": "self"}
```

이 JSON은 Cron 작업 전체가 아닌 **delivery 설정 부분**입니다. `last` 채널에 의존하지 마세요.
브리지는 별도 스케줄러를 만들지 않습니다. `!ai 10분 뒤 알려줘`는 기존 에이전트의 Cron 도구와
승인 정책이 허용하는 경우에만 작업이 생성됩니다. 실제 모델·Cron 왕복은 출시 전 검증 대상입니다.

## 상태 해석

| 상태/코드 | 의미와 조치 |
| --- | --- |
| `user_active` | 키보드/마우스 사용 중. 입력이 멈추면 재개합니다. |
| `desktop_locked` | 잠금 상태. 잠금 해제 후 새 스냅샷부터 관찰합니다. |
| `self_window_not_unique` | 지정한 본인 방 창이 없거나 중복. 창을 하나만 열고 제목을 확인하세요. |
| `self_room_type_unverified` | 제목 외에 본인 방 증거를 확인하지 못함. 해당 클라이언트는 P0 미지원 상태입니다. |
| `unsupported_control_tree` | 예상한 카카오톡 컨트롤이 없음. 클라이언트 버전별 검증이 필요합니다. |
| `clipboard_format_not_restorable` | 이미지/OLE/파일 클립보드가 있어 대기. 사용자가 필요 내용을 보관한 뒤 텍스트를 복사하면 재개합니다. |
| `user_draft_present` | 입력창에 사용자 초안이 있음. 직접 전송하거나 별도 보관 후 비우세요. |
| `focus_changed` / `clipboard_owner_changed` | 다른 작업과 충돌. 안전한 상태에서 재시도하거나 `unknown`으로 남습니다. |
| `connection_failed` | Gateway 버전·플러그인 상태·페어링·loopback 연결 확인. 연속 5회 실패하면 감시를 멈춥니다. |
| `unknown` | 보냈는지 확인 불가. 자동 재발송하지 않으므로 대화창에서 확인하세요. |
| `expired` | 최초 대기 후 15분 경과. 오래된 알림을 한꺼번에 보내지 않습니다. |
| `inbound_queue_full` / `outbound_queue_full` | 큐 포화. 추가 명령을 멈추고 기존 처리 상태를 확인하세요. |

창 닫기는 트레이로 숨깁니다. **일시 정지**는 작업 중지를 요청하고 진행 중 UI 동작이 끝나기를
기다립니다. 다시 연결하면 과거 스냅샷을 재처리하지 않습니다. **종료**는 작업이 끝난 뒤 앱을 닫습니다.
로그인 시 자동 실행을 선택해도 잠금 화면에서는 UI 자동화를 하지 않습니다.

## 진단

**진단 내보내기**는 사용자가 지정한 ZIP에 OS·브리지 버전·상태별 건수만 저장합니다. 카카오톡 대화,
클립보드, 설정 파일, 토큰은 포함하지 않습니다. 로그/진단을 이슈에 올리기 전 내용을 확인하세요.
실패를 해결하려고 `unknown` 레코드나 DB를 삭제하면 중복 방지 정보가 사라집니다.
